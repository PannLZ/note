## 摘要

多模态金融推理需要整合异质信息源，包括文本上下文、视觉信号以及领域专门知识。尽管近期已有显著进展，多模态大语言模型（MLLMs）仍会受到感知错误和知识不足的影响，从而产生错误的中间证据，并最终导致不可靠的推理结果。本文提出 SEA（Step-wise Evidence Acquisition，逐步证据获取），这是一个多智能体框架，将多模态金融推理建模为任务分解、证据获取与推理不断迭代的过程。

多智能体 SEA 引入一个规划器智能体，将复杂问题分解为一系列子任务，并在统一通信协议下生成自然语言查询。这些查询会被路由到专门的证据搜索智能体，由它们分别从视觉输入、文本上下文和外部金融知识中检索互补证据。检索到的信息被累积到一个动态演化的证据状态中，使推理智能体能够执行逐步的、基于证据的推断。作者在金融多模态基准上的大量实验表明，与强基线相比，SEA 显著提升了推理准确率和鲁棒性。进一步分析显示，该框架能够有效缓解感知错误并提升推理表现。

## 1. 引言

多模态大语言模型（MLLMs）的最新进展显著提升了 AI 系统整合视觉与文本信息的能力。这些模型在视觉问答、多模态推理等广泛任务中表现较强。然而，它们在多模态金融推理与问答任务上的表现仍远不能令人满意。金融问题通常要求精确解释数值信息、运用领域专门知识，并对文本、表格、金融图表等异质输入进行多步推理，这给当前多模态模型带来了显著挑战。

最新金融基准（如 FinMMR、FAMMA 和 FinMME）发现，最先进的 MLLMs 仍会在可靠金融推理上持续失败。这些失败主要来自感知错误（误读图表）、上下文误解（误解约束）和知识不足（缺少领域公式）。这些问题来源不同，却都汇聚到一个关键失败点：模型无法获得正确的中间证据。因此，模型会基于不完整或无关的信息继续推理，进而产生级联错误。

相比之下，人类专家的推理遵循一种明显的分解式模式。依据信息加工理论和有限理性理论，专家会采用逐步策略来管理有限的认知资源。专家不是一次性同时处理全部信息，而是使用目标导向的注意力，从异质来源中动态识别并抽取与任务相关的证据。在这种框架中，每一个推理步骤都会决定下一步所需的具体证据，因此准确获取证据成为成功推断的瓶颈。这说明，金融推理表现受到限制，可能并不主要是因为原始逻辑能力不足，而是因为模型在中间步骤中检索精确、任务条件化信息的能力不足。

这一观察引出一个根本问题：多模态金融推理的瓶颈究竟是推理能力本身，还是在中间步骤中获取准确且任务相关证据的能力？作者假设，推理错误的主要来源并不是推理能力缺陷，而是错误或不完整的中间证据。

基于这一动机，本文提出面向多智能体系统的 SEA（逐步证据获取），以解决由中间证据质量差导致的级联推理失败。SEA 明确地将多模态金融推理建模为一个逐步获取证据并进行推理的过程。它并不强迫单一模型一次性处理所有多模态输入，而是把推理过程分解为一系列子任务，每一步都识别并检索后续推断所需的具体证据。

具体而言，规划智能体首先将任务分解为子任务，并确定每一步需要的信息。随后，它生成有针对性的证据搜索查询，并将其路由给专门的智能体，由后者分别从金融图像、文本上下文和外部金融知识等不同来源中抽取信息。检索到的证据会累积到共享证据记忆中，并用于指导逐步推理。为了支持智能体之间的协作，SEA 采用基于查询的通信机制，使智能体之间可以进行有针对性的证据交换。规划器并不依赖复杂的结构化协议，而是发出简洁的自然语言查询，专门智能体返回聚焦的响应。该设计类似人类专家解决金融问题的方式：通过提出有针对性的问题来获得必要信息，从而减少冗余信息，并提高中间证据质量。

作者在 FinMR、FAMMA 和 MMMU-Finance 三个基准上评估了所提出的多智能体 SEA。实验结果表明，SEA 相比当前强基线表现更好，平均准确率提升 13.68%。此外，与静态策略相比，作者提出的动态任务分解策略平均带来 6.14% 的准确率提升。最后，基于查询的通信机制至少比流水线式、控制器式和辩论式机制高出 4.17%，说明该查询式方法能更好地协调多智能体协作，并为下游推理提供更高效用的证据。

本文贡献可概括如下：

- 提出 SEA，一个显式建模任务分解、证据获取和证据引导推理的多智能体框架，使视觉、文本和知识信息能够被动态整合。
- 引入基于查询的通信机制，智能体通过简洁、带步骤条件的自然语言查询进行交互，从而实现有效且可解释的证据交换。
- 在三个多模态金融推理基准上的大量实验证明，SEA 持续优于强基线，并通过提高中间证据质量来缓解感知错误和知识不足。

本文其余部分安排如下：第 2 节回顾金融多模态推理、主动信息获取和多智能体/工具增强推理相关工作；第 3 节介绍 SEA 框架，包括问题形式化、规划器引导的任务分解、多源证据获取、证据引导推理和基于查询的通信协议；第 4 节描述实验设置、基准数据集和基线方法；第 5 节报告主要实验结果，并进一步分析动态子任务生成、证据获取质量、智能体通信策略和剩余错误模式；第 6 节总结全文并讨论未来方向。

## 2. 相关工作

### 2.1 金融多模态推理

金融领域具有复杂决策过程、领域专门知识和精细分析等特征。LLMs 已在增强金融推理和分析任务方面展现出巨大潜力，例如投资决策和市场情绪分析。近期评估表明，LLMs 在文本金融推理数据集上表现较强，包括 TAT-QA 和 FinQA。然而，现实世界中的金融推理很少只依赖单一文本来源，通常需要整合来自多个来源的异质信息。

一般而言，金融多模态推理任务可以分为两类：知识驱动推理和感知驱动推理。知识驱动推理要求 MLLMs 使用深入的金融专业知识，处理高级金融术语，并理解细微的上下文信息。相比之下，感知驱动推理主要评估视觉能力，需要解释复杂金融视觉数据，如图表、曲线图和表格。尽管 MLLMs 已在许多领域的多模态任务中取得较好表现，但在 FinMR、FAMMA 和 FinMME 等金融多模态基准上的表现仍然较弱。知识驱动推理受限于模型对金融专业知识和隐含专业惯例掌握不足；感知驱动推理则受限于模型难以从密集图表和表格中准确抽取细粒度信息。因此，MLLMs 经常遗漏正确金融推理所需的关键知识、数值细节和视觉线索。

除了面向基准的金融推理，近期工作也探索了用于金融决策的 LLM 智能体，尤其是在交易场景中。TradingAgents 通过多个专门智能体模拟真实交易公司，包括基本面分析师、情绪分析师、技术分析师、交易员、多头和空头研究员以及风险经理。近期综述进一步总结了基于 LLM 的金融交易智能体的架构、数据输入、回测协议和挑战。这些工作展示了基于智能体的金融决策系统在金融领域的潜力。然而，它们主要关注市场交易和投资组合动作，而本文研究的是围绕图表、表格、文本上下文和领域知识的多模态金融推理。

### 2.2 主动信息获取

顺序信息获取已被广泛研究，用于减少不必要计算并提升决策效率。自适应计算的早期工作提出了动态推断机制，例如自适应计算时间，使神经网络在推理过程中学习何时停止。相关方法还包括早退 Transformer 和选择性注意力机制，它们动态分配计算资源。除了以效率为核心的自适应模型，主动特征获取也在决策理论框架下被研究。有成本特征的分类任务被形式化为强化学习问题，智能体顺序决定观察哪些特征。类似地，不确定性下的顺序特征获取用于平衡准确率和获取成本。这些方法显式建模信息成本，但主要关注表格或静态特征设定。在视觉和多模态领域，主动感知通过基于 glimpse 的模型和顺序注意力机制学习下一步应关注何处。最近，Transformer 中的自适应 token 选择策略会动态剪除无关 token，以提升效率。

近期 MLLMs 研究也强调了选择性使用视觉信息的重要性。视觉上下文学习通过检索视觉示例、根据任务意图总结图像，并构造面向意图的示例来提升 MLLMs 的下游推理能力。这一方向表明，多模态推理受益于选择与任务相关的视觉信息，而不是不加区分地编码所有视觉内容。

然而，现有方法通常优化的是计算效率、特征成本或示例选择，而不是结构化推理中的证据效用。相比之下，本文将多模态金融推理视为一个顺序信息获取过程：模型显式决定需要从图像、文本上下文和外部金融知识库中获取什么证据，以及何时停止。系统不是被动编码所有模态，而是主动控制何时以及如何检索证据，从而实现需求驱动的推理。

### 2.3 多智能体与工具增强推理

LLMs 的最新进展表明，集成外部工具或协调多个智能体可以显著增强推理能力。ReAct 等工具增强框架交替执行推理与行动，使模型能够在推理过程中查询外部环境。类似地，ToolFormer 使语言模型能够在生成过程中决定何时调用外部工具。这些方法让语言模型超越了被动文本生成，能够与计算器、搜索引擎和代码执行环境等结构化资源交互。

检索增强推理通过将外部知识引入中间推理步骤，进一步提升复杂推理的事实性和可靠性。例如，RARE 在互惠推理框架中加入检索动作和检索增强事实性评分器，以优先选择事实基础更充分的推理路径。关于多语言知识图谱的相关研究也表明，结构化知识、关系语义和上下文增强对于知识密集推理与对齐任务很重要。这些研究说明，外部知识源能够为复杂推理提供有用的语义和关系证据。

与此同时，多智能体推理系统会把复杂任务分解为规划器、执行器和验证器等专门角色。AutoGen 等框架通过迭代通信协调多个基于 LLM 的智能体，使其能够跨多个步骤协作解决问题。近期研究还将角色专门化协作扩展到高风险多模态领域。例如，MAM 将多模态医学诊断分解给多个专门智能体，包括全科医生、专家团队、放射科医生、医疗助理和主任，展示了文本、图像、音频和视频模态上模块化协作的有效性。这些系统通常依赖基于提示的角色分配和预定义通信协议来引导智能体交互。

尽管这些方法有效，现有大多数方法仍主要由提示驱动，并面向通用推理、交易决策、检索增强知识推理或特定领域诊断。它们没有显式解决多模态金融推理中的关键挑战：从文本上下文、表格、图表和金融知识等异质来源中准确获取证据。此外，现有框架往往缺少有针对性的信息搜索机制，容易产生冗余或错配的证据，并把错误传播到下游推理。

相比之下，本文提出一个面向多模态金融推理的结构化证据获取框架。该框架不是依赖隐式工具使用、静态示例、单纯检索或松散协调的智能体交互，而是设计了一种简单有效的通信协议，使智能体能够迭代交换简洁、任务驱动的查询和响应。通过聚焦有针对性的信息获取和智能体通信，框架在不需要额外模型训练的情况下，提高了证据相关性和下游推理可靠性。

## 3. 方法

### 3.1 问题形式化

本文将多模态金融推理研究为异质输入上的、顺序进行的、基于证据的决策问题。每个实例定义为：

\[
x=(C,I,Q,O)
\]

其中，\(C\) 表示文本上下文（例如问题上下文），\(I=\{v_1,\ldots,v_M\}\) 表示视觉输入集合（例如图表、表格或图像），\(Q\) 是问题，\(O=\{o_1,\ldots,o_K\}\) 是候选答案集合。真实答案 \(y\in O\)。

不同于常规的一次性预测，本文将推理建模为规划、证据获取与证据引导推理交替进行的迭代过程。在推理步骤 \(n\)，系统维护两个状态：证据状态 \(E_n\)，用于存储截至第 \(n\) 步检索到的全部证据；推理轨迹 \(R_n\)，用于存储截至第 \(n\) 步的全部中间推理输出。形式化地：

\[
E_n=\{e_1,\ldots,e_{|E_n|}\}, \quad R_n=\{r_1,\ldots,r_n\}
\]

过程从空记忆开始：\(E_0=\emptyset, R_0=\emptyset\)。目标是通过逐步收集任务相关证据，并让每一步推理都以累积证据为条件，预测最终答案 \(\hat{y}\in O\)。这种形式化显式区分了“需要什么信息”和“如何推断答案”，从而减少幻觉并提升可解释性。主要符号见附录 A。

### 3.2 SEA 概览

SEA（逐步证据获取）是一个多智能体框架，通过三个功能模块之间的闭环交互解决多模态金融推理：

1. 规划器智能体 \(A_P\)：将问题分解为逐步子任务，并发出证据搜索查询。
2. 证据搜索智能体集合 \(\{A_I,A_C,A_K\}\)：分别从视觉输入、文本上下文和外部金融知识中检索证据。
3. 推理智能体 \(A_R\)：基于检索到的证据进行中间推理，并在证据不足时报告问题。

SEA 以迭代方式进行。每一步中，规划器确定当前子任务，生成一组有针对性的自然语言查询，并判断当前证据是否足以停止。查询被路由到相应证据搜索智能体，其输出整合到共享证据状态中。随后，推理智能体基于当前子任务和累积证据更新推理轨迹。该过程重复进行，直到规划器判断可用证据足以回答原始问题。

这种设计显式地把多模态金融推理视为需求驱动的证据获取过程：系统不会一次性均匀处理所有信息，而是检索当前推理步骤所需的具体证据。

### 3.3 规划器引导的任务分解

规划器智能体 \(A_P\) 控制整体推理过程。在第 \(n\) 步，给定输入实例 \(x\)、前一证据状态 \(E_{n-1}\) 和前一推理轨迹 \(R_{n-1}\)，规划器输出：描述当前推理目标的子任务 \(T_n\)、用于证据获取的自然语言查询集合 \(Q_n=\{q_{n,1},\ldots,q_{n,L_n}\}\)，以及终止标志 \(s_n\in\{\text{continue},\text{stop}\}\)。形式化地：

\[
(T_n,Q_n,s_n)=A_P(x,E_{n-1},R_{n-1})
\]

子任务 \(T_n\) 指定推进推理过程所需的信息，例如从图表中提取某个数值、从上下文中识别约束，或检索领域公式。查询集合 \(Q_n\) 将该子任务具体化为可由专门智能体回答的信息请求。终止标志 \(s_n\) 表示当前证据状态是否已经足以回答原始问题：

\[
s_n=
\begin{cases}
\text{stop}, & \text{若 } A_P \text{ 判断 } (E_{n-1},R_{n-1}) \text{ 足以回答 } Q\\
\text{continue}, & \text{否则}
\end{cases}
\]

这种形式化使规划器成为自适应的，而不是静态的。规划器不会预先固定一条子任务链，而是根据已累积证据修正后续推理目标。对于金融推理而言，相关信息经常分散在文本、表格、图表和外部知识中，因此这种自适应分解尤其重要。

### 3.4 多源证据获取

给定第 \(n\) 步生成的查询集合 \(Q_n=\{q_{n,1},\ldots,q_{n,L_n}\}\)，每个查询会被路由给最合适的证据搜索智能体：

\[
a_{n,l}=\rho(q_{n,l}), \quad a_{n,l}\in\{A_I,A_C,A_K\}
\]

其中 \(\rho(\cdot)\) 表示路由函数。对应证据按如下方式检索：

\[
e_{n,l}=
\begin{cases}
A_I(I,q_{n,l}), & a_{n,l}=A_I\\
A_C(C,q_{n,l}), & a_{n,l}=A_C\\
A_K(D,q_{n,l}), & a_{n,l}=A_K
\end{cases}
\]

其中 \(D\) 表示外部金融知识库。第 \(n\) 步返回的证据集合为：

\[
\Delta E_n=\{e_{n,1},\ldots,e_{n,L_n}\}
\]

证据状态更新为：

\[
E_n=E_{n-1}\cup \Delta E_n
\]

三个证据搜索智能体具有互补角色。图像代理 \(A_I\) 从图表、表格和图像中抽取结构化视觉证据，例如数值、趋势和关系。上下文代理 \(A_C\) 从文本上下文中识别任务相关信息，包括变量、假设和问题约束。知识代理 \(A_K\) 从外部知识库 \(D\) 中检索金融概念、公式和领域原则。

SEA 的一个关键性质是证据获取带有步骤条件。系统不是一次性被动总结所有可用输入，而是在当前子任务需要时才检索证据。这提高了中间证据的相关性和精确性，而这对可靠的多步金融推理至关重要。

### 3.5 证据引导推理

更新证据状态后，推理智能体 \(A_R\) 执行当前推断步骤。在第 \(n\) 步，它接收子任务 \(T_n\)、更新后的证据状态 \(E_n\) 和前一推理轨迹 \(R_{n-1}\)，并产生中间推理输出 \(r_n\)：

\[
r_n=A_R(T_n,E_n,R_{n-1})
\]

推理轨迹随之更新：

\[
R_n=R_{n-1}\cup \{r_n\}
\]

证据获取与推理紧密耦合。如果当前累积证据不足（即推理智能体在某一步报告证据问题），规划器会在下一步生成新的子任务和附加查询。如果规划器判断证据足够，迭代过程终止并生成最终答案：

\[
\hat{y}=A_R^{final}(x,E_N,R_N)
\]

其中 \(N\) 是满足 \(s_N=\text{stop}\) 的最终推理步骤。

该设计确保最终决策基于显式证据轨迹，而不仅是隐式潜在推理。每个推理步骤都可以追溯到已检索证据，从而提升鲁棒性和可解释性。

### 3.6 基于查询的通信协议

SEA 使用有效的基于查询的通信协议来协调智能体。它不依赖复杂的符号消息传递或开放式多智能体辩论，而是让规划器通过简洁的自然语言查询与证据搜索智能体通信。这一设计有两个优点：第一，它自然契合现代 LLM/MLLM 智能体的能力；第二，它将信息交换约束在当前子任务所需证据范围内，减少冗余，并提高规划与检索之间的一致性。

该协议运行方式如下。每一步中，规划器首先决定推理是否应继续。如果 \(s_n=\text{stop}\)，系统终止证据获取，并使用累积证据和推理历史产生最终答案。否则，规划器生成查询集合 \(Q_n\)，每个查询被路由给一个专门证据搜索智能体，返回证据被加入共享记忆，用于下游推理。

#### 算法 1：SEA - 面向多模态金融推理的逐步证据获取

输入：实例 \(x=(C,I,Q,O)\)，知识库 \(D\)，最大步骤数 \(N_{max}\)  
输出：预测答案 \(\hat{y}\)

1. 初始化证据状态 \(E_0\leftarrow \emptyset\)。
2. 初始化推理轨迹 \(R_0\leftarrow \emptyset\)。
3. 对 \(n=1\) 到 \(N_{max}\)：
4. 由规划器得到 \((T_n,Q_n,s_n)=A_P(x,E_{n-1},R_{n-1})\)。
5. 若 \(s_n=\text{stop}\)，则生成 \(\hat{y}=A_R^{final}(x,E_{n-1},R_{n-1})\) 并返回。
6. 初始化本步证据集合 \(\Delta E_n\leftarrow \emptyset\)。
7. 对每个查询 \(q_{n,l}\in Q_n\)：
8. 用路由函数得到目标智能体 \(a_{n,l}=\rho(q_{n,l})\)。
9. 若目标为图像代理，则从视觉输入中检索证据。
10. 若目标为上下文代理，则从文本上下文中检索证据。
11. 若目标为知识代理，则从金融知识库中检索证据。
12. 将返回证据加入 \(\Delta E_n\)。
13. 更新 \(E_n=E_{n-1}\cup \Delta E_n\)。
14. 由推理代理得到 \(r_n=A_R(T_n,E_n,R_{n-1})\)。
15. 更新 \(R_n=R_{n-1}\cup \{r_n\}\)。
16. 若达到最大步数仍未停止，使用 \(A_R^{final}(x,E_{N_{max}},R_{N_{max}})\) 生成并返回最终答案。

## 4. 实验

### 4.1 实验设置

作者基于三个前沿模型实例化智能体：GPT-4o、Gemini-2.5-Flash 和 Claude-4-5-Sonnet。每个实验中，所有智能体使用相同的基础模型，以确保不同模型族之间比较公平。为了提高可复现性并减少多步推理中的随机性，所有智能体均使用确定性解码，温度设置为 0.0。每个智能体都被提示返回结构化 JSON 输出，包括规划器的停止决策、子任务、目标智能体和证据搜索查询。完整提示词见附录 B。

为解决通用 MLLMs 的领域知识限制，作者进一步使用专家标注解释数据构建了外部金融知识库 \(D\)。这些人工标注资源提供了金融概念、公式和应用场景的详细解释，因此可作为高质量外部金融专业知识库。知识代理根据规划器生成的查询，从该数据库中检索相关金融概念、公式和领域规则。

为了使整体推理过程在计算上可控，并避免不必要的长规划链，作者将最大规划步骤数设为 \(N_{max}=6\)。每一步中，规划器最多生成三个证据搜索查询，分别对应图像代理、上下文代理和知识代理。因此，单个样本的智能体调用次数上界为 \(1+N_{max}(1+3+1)\)：括号内三项分别对应每步一次规划器调用、最多三次证据代理调用和一次推理代理调用，额外一次调用用于最终答案生成。实际中，一旦规划器判断累积证据充分，推理过程会提前终止。

### 4.2 基准

作者在三个金融多模态推理基准上评估方法：FinMR、FAMMA 和 MMMU-Finance。这些基准在领域范围、问题类型、证据依赖和难度层级上不同，因此可用于评估 SEA 是否能泛化到不同金融推理场景。为防止知识泄漏，所有实验仅在测试集上进行，因为 FinMR 和 FAMMA 的训练集被用于构建外部金融知识库。

FinMR 是专家级金融多模态推理基准，包含 3200 个金融推理问题。每个实例包括详细文本上下文、一个或多个金融图像、候选选项和专家标注解释。FinMR 旨在评估专业层级金融推理，覆盖多样化金融主题，并要求整合数学推理、领域知识和视觉解释。在本文评估子集中，FinMR 同时包含数学推理问题和金融专业知识问题。数学子集主要要求数值计算、公式应用和定量比较；专业知识子集则更聚焦概念理解、金融解释和领域判断。因此，FinMR 是本文评估中最知识密集、最专家导向的基准。

FAMMA 是一个多语言金融多模态推理基准，旨在评估大学层级和高级金融专业知识。原始基准包含从教材和考试中收集的金融问答对，跨越公司金融、资产管理和金融工程等多个金融子领域。每个问题配有一个或多个图像，如表格、图表和示意图，要求模型结合文本理解、视觉证据抽取和金融知识。与 FinMR 相比，FAMMA 更强调多语言性和学术金融知识。在本文评估子集中，FAMMA 平均分为数学推理和专业知识导向问题，用于测试 SEA 是否对定量和概念金融推理都有效。

MMMU-Finance 是 Multi-discipline Multimodal Understanding 基准中的金融子集。MMMU 旨在评估广泛学科中的大学层级多模态理解和审慎推理。本文使用金融相关子集，其中样本来自 Finance、Economics 和 Accounting。与专门构建用于金融多模态推理的 FinMR 和 FAMMA 不同，MMMU-Finance 提供更广泛的学术场景，问题更像标准化考试。值得注意的是，该子集中约 95% 的视觉输入是金融表格，因此特别适合评估基于表格的数值推理和结构化金融信息抽取。

总体而言，三个基准提供了互补的评估设置：FinMR 测试带丰富文本和视觉证据的专家级金融推理；FAMMA 评估跨异质视觉输入的多语言大学层级金融推理；MMMU-Finance 则考察更广泛的学术金融推理，尤其强调基于表格的视觉证据。因此，在这些数据集上评估 SEA 可以检验其在不同难度层级、证据来源和金融推理类型上的泛化能力。

### 4.3 基线

**CoT** 指示 LLMs 在给出最终答案前生成中间推理步骤，例如“让我们一步一步思考”。它是一个强单智能体基线，能够提升推理透明度，并将复杂金融问题拆解为顺序推断步骤。

**MAD** 研究多智能体辩论系统中决策协议的影响。多个智能体先生成候选解，再通过若干轮讨论交换推理。随后使用预定义决策协议，如投票或共识，确定最终答案。

**RAA** 是一个面向金融问答的角色感知多智能体框架，包含证据检索器、基于 CoT 的生成器和专家审阅器。检索器收集金融知识，生成器产生初始答案，审阅器通过批评和修正来完善答案。

SEA 在数学问题上的提升尤为明显，因为这类问题需要精确数值推理和公式应用。例如，在 FinMR Math 子集上，SEA 使用 Gemini-2.5-Flash 达到 66.20% 准确率，使用 Claude-4-5-Sonnet 达到 76.50%，明显超过其他推理策略。这说明动态检索相关公式和金融概念有助于缓解计算错误并提升推理可靠性。

另一个重要观察是，SEA 对所有评估基础模型都能稳定提升，包括 GPT-4o、Gemini-2.5-Flash 和 Claude-4-5-Sonnet。尽管模型架构和能力存在很大差异，该框架在 FinMR、FAMMA 和 MMMU 上都带来稳定增益，说明 SEA 具有模型无关性，可作为增强金融任务中多模态推理的一般框架。

为进一步评估提升的可靠性，作者基于表 4 中的准确率进行非参数统计显著性分析。由于比较方法在相同模型-数据集-子集设定下评估，并且准确率可能不满足正态假设，作者使用非参数检验。每个模型-数据集-子集组合被视为一个评估设置，共得到 21 个配对观察值。

#### 表 5：21 个评估设置上的统计显著性分析

| 统计检验 | 比较 | 结果 |
|---|---|---|
| Friedman 检验 | CoT vs. MAD vs. RAA vs. SEA | \(\chi^2_F(3)=55.23, p=6.14\times10^{-12}\) |
| Friedman 平均排名 | SEA / RAA / MAD / CoT | 1.00 / 2.38 / 2.69 / 3.93 |
| Nemenyi 事后检验 | SEA vs. 所有基线 | 在 \(\alpha=0.05\) 下显著 |
| Wilcoxon 符号秩检验 | SEA vs. CoT | \(p=9.54\times10^{-7}\) |
| Wilcoxon 符号秩检验 | SEA vs. MAD | \(p\approx5.94\times10^{-5}\) |
| Wilcoxon 符号秩检验 | SEA vs. RAA | \(p\approx5.93\times10^{-5}\) |

Friedman 检验表明四种方法之间存在显著性能差异。SEA 获得最佳平均排名 1.00，随后是 RAA、MAD 和 CoT。Nemenyi 事后检验显示，SEA 与所有基线之间的排名差异均大于 \(\alpha=0.05\) 下的临界差异，说明 SEA 在各评估设置中显著优于基线。双侧 Wilcoxon 符号秩检验也进一步确认 SEA 相对 CoT、MAD 和 RAA 的提升具有统计显著性。

总体而言，结果表明，显式区分信息获取和推理对于解决复杂多模态金融问题至关重要。SEA 在推理前动态检索任务相关证据，相比基于提示和现有多智能体方法，显著提升了推理准确率和鲁棒性。

### 5.2 消融研究

为了量化 SEA 各组件的贡献，作者系统性移除完整框架中的关键模块进行消融研究。由于基于 Claude-4-5-Sonnet 的完整 SEA 在表 4 中整体表现最强，作者以该模型作为所有消融实验的基础。这些分析旨在考察视觉 grounding、多智能体通信和专门化证据获取如何共同影响金融多模态推理表现。

#### 表 6：SEA 在三个基准上的消融研究（基础模型：Claude-4-5-Sonnet）

| 方法 | FinMR | FAMMA | MMMU |
|---|---:|---:|---:|
| 完整 SEA | 78.49 | 64.50 | 82.70 |
| 去除规划器 | 63.79 | 60.00 | 65.30 |
| 去除智能体通信 | 64.69 | 61.00 | 73.21 |
| 去除证据搜索智能体 | 72.19 | 62.30 | 78.22 |

**SEA 去除规划器。** 在完整框架中，规划智能体将任务分解为逐步子任务，并生成针对性查询，引导每个推理步骤中的证据获取。在该变体中，作者完全移除规划智能体。每个证据搜索智能体只基于固定、通用指令运行，例如理解图像、上下文和问题以抽取相关证据，或从金融知识库中检索知识，而没有步骤级指导。收集到的证据直接交给推理智能体。表 6 显示，该变体略优于标准 CoT，但明显弱于完整 SEA。这说明证据搜索智能体虽有益，但其效果高度依赖细粒度、步骤条件化的指导。缺少显式规划机制时，证据检索会变得粗糙，并且与不断变化的推理需求不够一致，导致下游表现不佳。

**SEA 去除智能体通信。** 在该变体中，作者移除规划器、证据搜索智能体和推理智能体之间的迭代通信机制。规划器只生成一次推理计划和查询，证据搜索智能体一次性检索信息，推理智能体再根据收集到的证据产生最终答案。相比完整 SEA，该变体产生最大整体退化：FinMR 降至 64.69%，FAMMA 降至 61.00%，MMMU-Finance 降至 73.21%。结果说明，迭代多智能体通信显著改善中间证据质量，并使规划、证据收集和推理之间的协调更有效。

**SEA 去除证据搜索智能体。** 为评估有针对性证据获取的重要性，作者移除证据搜索智能体，仅保留规划器和推理智能体。在该设定下，系统无法再通过专门智能体从不同来源抽取证据。各数据集表现均下降：FinMR 为 72.19%，FAMMA 为 62.30%，MMMU-Finance 为 78.22%。虽然该变体仍强于没有规划器或通信的设置，但始终弱于完整 SEA，表明专门证据搜索智能体对准确金融多模态推理有实质贡献。

总体而言，消融结果确认三个组件均有益，但贡献强度不同。迭代智能体通信带来最大性能增益，说明智能体之间的协调是 SEA 的核心。规划器对视觉输入的直接访问也很重要，尤其适用于需要精确视觉 grounding 的任务。专门证据搜索智能体进一步通过支持从异质来源进行有针对性的信息获取来提升表现。完整 SEA 因此在 FinMR、FAMMA 和 MMMU-Finance 上取得最佳结果。

### 5.3 动态子任务生成的效用分析

作者在 FinMR 数据集上比较动态子任务生成与静态分解策略。静态分解中，所有子任务在开始时预先定义，并在整个推理过程中保持固定。结果显示，动态子任务生成在所有基础模型上都持续优于静态分解。尤其是 Gemini-2.5-Flash 的提升很大（+9.43%），GPT-4o 也有明显提升（+3.93%），说明动态规划的收益在不同能力模型上都具有鲁棒性。

性能提升来自动态规划的自适应性质。静态分解在没有中间证据的情况下确定推理轨迹，因此容易受到早期规划错误影响，且后续无法修正。这一限制在 FinMR 中尤其明显，因为相关信息常分散在文本上下文、视觉输入和领域知识中，需要灵活且迭代的推理。相比之下，动态子任务生成使规划器能够基于不断演化的证据状态迭代更新后续子任务。系统可以根据新获取证据细化推理目标、纠正早期误解，并在每一步聚焦最相关的信息。

### 5.4 证据获取的效用分析

为评估不同智能体获取证据的质量，作者在 FinMR、FAMMA 和 MMMU-Finance 基准上进行了细粒度分析。

**基于案例的分析。** 对每个数据集，作者随机采样推理过程中生成的 100 个中间查询，并评估对应智能体响应的正确性。不同模态采用不同评估策略：图像代理由于视觉解释复杂性，使用人工评估；上下文代理使用 GPT-5 判断在给定查询和上下文下生成答案是否正确；知识代理将响应与数据集提供的真实解释对比，并使用 LLM 判断正确性。

结果表明，三个智能体整体都能产生高质量证据，但在不同模态上表现不同。上下文代理在各数据集上持续表现强劲，例如在 FinMR 上达到 95%，说明它能可靠地抽取并处理文本上下文。知识代理也较稳健，在 MMMU-Finance 上最高达到 93%，说明它能有效检索和应用领域专门金融知识。相比之下，图像代理准确率较低，例如在 FAMMA 上为 63%，反映出金融图表和表格中的细粒度视觉感知本身较难。不过，它在 FinMR 上仍达到 75%，说明当视觉信息必不可少时，它仍提供有用的互补证据。

智能体之间的差异揭示了一个重要洞见：证据质量依赖模态，多模态推理错误往往来自较弱的感知模块。这进一步支持 SEA 的设计，即多个专门智能体共同贡献证据，使较强模态（如上下文和知识代理）能够补偿较弱模态（如图像代理）。整体结果表明，SEA 能够跨模态可靠获取高质量中间证据，而这正是提升下游推理表现的关键基础。

**证据扰动分析。** 为进一步考察中间证据质量如何影响最终推理结果，作者使用 Claude-4-5-Sonnet 作为基础模型进行证据扰动分析。对每个基准，作者分别以 0%、25%、50%、75% 和 100% 的比例删除知识证据、图像证据和文本上下文证据，然后评估最终推理准确率。该受控设定能够量化不同证据类型完整性对最终答案的影响。作者还报告了每个准确率的 95% Wilson 置信区间，并以误差条可视化。

结果显示，随着证据删除比例增加，三个基准上的准确率总体下降，说明中间证据直接支撑最终推理过程。在 FinMR 上，当知识、文本上下文和图像证据被完全移除时，准确率分别从 78.49% 降至 74.23%、73.86% 和 73.24%。最大退化来自移除图像证据，说明视觉 grounding 对 FinMR 尤其重要。在 FAMMA 上，完全移除知识、图像和文本上下文证据后，性能从 64.50% 分别降至 63.25%、63.08% 和 63.40%。虽然绝对下降较小，但一致下降趋势说明三类证据都对最终预测有贡献。在 MMMU-Finance 上，完全移除知识、图像和文本上下文证据后，准确率从 82.70% 分别降至 79.58%、79.33% 和 79.75%，再次说明多模态证据和金融知识对可靠推理都很重要。

总体而言，这些扰动结果及置信区间提供了直接经验依据：SEA 的有效性与中间证据完整性密切相关。随着删除比例增加而出现的性能退化确认了中间证据的效用和质量。如果获取的证据大多是噪声、冗余或与推理任务弱相关，那么删除更多证据不应导致性能持续下降。相反，观察到的退化说明 SEA 收集的证据通过约束候选答案并支持中间决策，对推理有正向贡献。由于每次只移除一种证据类型，剩余证据源仍能部分补偿缺失模态，这也突显了 SEA 多智能体证据获取机制的互补性。

### 5.5 基于查询的智能体通信效用分析

为评估不同协作机制的有效性，作者比较了四种代表性范式：

1. 流水线式协作：智能体顺序运行，没有交互。
2. 控制器式协调：中央规划器将子任务分配给不同模块，但没有显式查询-响应通信。
3. 辩论式协作：智能体进行多轮对抗式讨论。
4. 本文的查询驱动交互协作：规划器与证据搜索智能体之间进行结构化查询-响应通信。

为公平比较，所有通信基线均使用相同基础模型和相同输入上下文。流水线式基线遵循顺序证据检索与推理流程，类似角色感知金融智能体。控制器式基线遵循 AutoGen 风格系统的集中协调范式，由控制器给专门智能体分配子任务，但不使用显式查询-响应证据获取。辩论式基线遵循多智能体辩论协议，多个智能体独立生成答案，并在产生最终决策前交换批评意见。相比之下，SEA 使用规划器生成的、带步骤条件的查询，在每个推理步骤从最相关智能体中显式获取缺失证据。

#### 表 7：代表性多智能体通信范式比较

| 通信方法 | FinMR | FAMMA | MMMU-Finance |
|---|---:|---:|---:|
| 流水线式：Role-aware Agent | 70.31 | 60.33 | 67.66 |
| 控制器式：AutoGen-style | 67.44 | 56.78 | 65.59 |
| 辩论式：Multi-agent Debate | 72.33 | 57.32 | 70.69 |
| 查询式：SEA（本文） | 78.49 | 64.50 | 82.70 |

表 7 显示，查询驱动交互在所有基准上持续优于其他协作范式。在 FinMR 上，SEA 达到 78.49% 准确率，显著超过流水线式（+8.18%）、控制器式（+11.05%）和辩论式（+6.16%）协作。在 FAMMA 和 MMMU-Finance 上也观察到类似提升，MMMU-Finance 的增益尤其明显：相对控制器式提升 +17.11%，相对流水线式提升 +15.04%。

这些结果揭示了几个重要洞见。第一，纯顺序协作不足以应对复杂多模态金融推理。流水线式方法缺少动态获取缺失信息的能力，导致中间证据不完整或错误。第二，控制器式协调虽然引入任务路由，但支持基于证据推理的能力仍有限。规划器可以决定调用哪个模块，但它委托的是整个子任务，而不是显式识别并检索缺失信息。因此，推理过程仍然隐式，系统可能无法获得准确决策所需的精确证据。第三，虽然辩论式协作提供更强交互，但非结构化或对抗式通信并不必然提升推理表现。其在 FAMMA 上相对较低的表现说明，多轮讨论可能引入冗余或分散核心任务注意力，而没有有效解决缺失证据问题。此外，辩论式方法通信开销更高，却不能保证更准确的信息获取。

相比之下，SEA 的查询驱动框架通过有针对性且高效的证据获取实现最佳表现。每一步中，规划器显式识别缺失信息，并形成任务特定查询，从最相关智能体检索证据。这种结构化通信范式避免了流水线执行的僵化和开放式辩论的低效，同时克服了控制器式协调中隐式推理的局限。因此，它产生更准确的中间证据，并带来更可靠的最终预测。这些结果说明，并非所有交互形式都同样有效。对于多模态金融任务而言，相比无交互、隐式任务委托或过度交互，最小但有针对性的查询式通信在效率和推理准确率之间提供了最合适的平衡。

### 5.6 错误分析

尽管 SEA 在 FinMR 和 MMMU-Finance 上表现较强，作者观察到它在 FAMMA 基准上的准确率相对较低。为分析系统在 FAMMA 上的局限，作者随机采样 100 个错误案例，并将错误分类如下：

**跨图像推理错误（46%）。** 最大比例的错误出现在同一问题包含多个图表或表格的情形。这些问题要求模型从多个视觉来源中抽取数值信息并正确聚合。许多情况下，系统未能准确合并不同图表的信息，导致中间值和最终答案错误。

**文本-图像对齐错误（23%）。** 另一类常见错误发生在问题包含长文本上下文并伴随图像时。在这些情况下，模型有时难以正确对齐文本描述与相关视觉元素。因此，来自文本或图像的重要信息可能在推理中被忽略。

**场景特定知识错误（10%）。** 作者还观察到与金融知识应用相关的错误。虽然系统能够检索通用金融公式或概念，但有些问题要求将这些公式适配到特定金融场景。在这些情况下，模型偶尔会直接应用标准公式，而没有正确考虑上下文假设，从而造成推理错误。

**其他（21%）。** 剩余错误包括数值计算错误和偶发的推理不一致。

除上述经验分类外，这些错误还暴露了 SEA 的几个组件级局限。第一，框架依赖规划器生成子任务的质量。当问题要求整合多个图表、表格或文本约束时，不完整的子任务分解可能使系统忽略必要证据。第二，尽管证据搜索智能体提高了模块化程度，它们仍可能返回不完整或部分错配的证据，尤其是在长文本上下文需要与特定视觉元素匹配时。第三，当前框架没有显式解决不同智能体返回证据之间的冲突。因此，矛盾或不足的证据可能传播到推理智能体，并导致错误中间推理。最后，虽然知识代理能够检索通用金融概念和公式，但某些问题要求将这些原则适配到场景特定假设，这仍然具有挑战。作者认为，未来工作应纳入规划器验证、跨来源证据一致性检查，以及更稳健的多视觉和文本来源证据聚合机制。

## 6. 结论

本文提出 SEA，一个用于多模态金融推理的多智能体框架，显式建模任务分解、证据获取和推理之间的交互。通过引入规划器引导的、基于查询的通信协议，SEA 能够从视觉、文本和知识输入等异质来源中动态检索带步骤条件的证据。SEA 的关键洞见是：多模态金融任务中的推理错误往往源于不足或错误的中间证据。通过维护显式证据状态，并让每个推理步骤都基于检索信息，SEA 有效提升了可解释性。经验结果表明，SEA 在多个基准上实现持续增益，尤其适用于需要跨模态整合和领域专门知识的场景。总体而言，SEA 在复杂多模态设置中有效整合了感知、知识与推理，为构建更可靠、更可解释的金融推理系统提供了有前景的方向。

## 7. 局限性

虽然 SEA 展现了较强的性能提升，但仍存在若干局限。首先，该框架依赖多个基于大模型的智能体，相比单模型方法会引入额外计算开销。尽管基于查询的通信协议较简单，智能体之间的迭代交互仍可能增加真实应用中的延迟。第二，SEA 的有效性取决于证据搜索智能体的质量。视觉感知、信息抽取或知识检索中的错误仍可能通过系统传播，并影响下游推理。最后，本文实验聚焦金融多模态基准，SEA 是否能泛化到科学推理或医学推理等其他领域，仍有待进一步探索。

## 附录 B：SEA 的提示词模板

为提高可复现性，作者提供了 SEA 中使用的提示词模板。每个智能体在同一实验中使用相同基础 MLLM，但被分配角色特定指令。规划器智能体生成带步骤条件的子任务和证据搜索查询；证据搜索智能体返回模态特定证据；推理智能体基于累积证据状态执行证据 grounded 推断。

### B.1 规划器智能体提示词

**系统输入。** 你是多模态金融推理逐步证据获取框架中的规划器智能体。给定原始实例、累积证据和中间推理轨迹，你的任务是判断当前证据是否足以回答问题。如果证据足够，输出 `stop`。否则，生成下一个子任务，并形成有针对性的证据搜索查询。

可用证据搜索智能体包括：`Image Agent`，从图表、表格、图像和其他视觉输入中抽取信息；`Context Agent`，从文本上下文中检索信息；`Knowledge Agent`，提供金融概念、公式、定义和领域知识。

你只应生成下一个必要子任务，避免冗余查询，并将每个查询精确分配给一个智能体。不要直接回答问题。只有当累积证据和推理轨迹足以让推理智能体推导最终答案时才停止。最大规划步骤数为 \(N_{max}=6\)。仅返回如下 JSON 对象：

```json
{
  "status": "continue or stop",
  "subtask": "<next reasoning objective, or None>",
  "queries": [
    {
      "agent": "Image Agent / Context Agent / Knowledge Agent",
      "query": "<targeted evidence-seeking query>"
    }
  ]
}
```

如果 `status` 为 `stop`，将 `subtask` 设为 `None`，并将 `queries` 设为空列表。

**用户输入。**

```text
Context: {context}
Question: {question}
Options: {options}
Images: {images}
Step ID: {step_id}
Accumulated Evidence: {evidence_state}
Intermediate Reasoning Trajectory: {reasoning_trajectory}
Return only the JSON object.
```

### B.2 证据搜索智能体提示词

#### 图像代理提示词

**系统输入。** 你是多模态金融推理逐步证据获取框架中的图像代理。给定规划器查询和视觉输入，你的角色是只抽取该查询所需的视觉证据。视觉输入可能包括图表、表格、图像、绘图或截图。

你应从图像中识别相关数值、标签、坐标轴、单位、表格项、趋势、比较和关系。不要推断没有依据的信息。如果请求的证据不可见，请说明不可用。仅返回如下 JSON 对象：

```json
{
  "agent": "Image Agent",
  "query": "<planner query>",
  "evidence": "<extracted visual evidence>"
}
```

**用户输入。**

```text
Images: {images}
Planner Query: {query}
Return only the JSON object.
```

#### 上下文代理提示词

**系统输入。** 你是 SEA 中的上下文代理。给定规划器查询和文本上下文，你的角色是只抽取该查询所需的文本证据。

你应识别相关事实、变量、假设、约束、数值量、时间条件、上下文中给出的定义，以及实体或变量之间的关系。如果请求证据没有在上下文中陈述或暗示，请说明不可用。仅返回如下 JSON 对象：

```json
{
  "agent": "Context Agent",
  "query": "<planner query>",
  "evidence": "<extracted textual evidence>"
}
```

**用户输入。**

```text
Context: {context}
Planner Query: {query}
Return only the JSON object.
```

#### 知识代理提示词

**系统输入。** 你是 SEA 中的知识代理。给定规划器查询和从外部金融知识库 \(D\) 中检索到的条目，你的角色是只提供该查询所需的金融知识。

你应检索相关金融概念、数学公式、定义和领域特定推理原则。如果请求知识在检索条目中不可用，请说明不可用。仅返回如下 JSON 对象：

```json
{
  "agent": "Knowledge Agent",
  "query": "<planner query>",
  "evidence": "<retrieved financial knowledge>"
}
```

**用户输入。**

```text
Retrieved Knowledge Entries: {retrieved_knowledge_entries}
Planner Query: {query}
Return only the JSON object.
```

### B.3 推理智能体提示词

**系统输入。** 你是 SEA 中的推理智能体，这是一个面向多模态金融推理的逐步证据获取框架。

在每个推理步骤中，你会得到当前子任务、更新后的证据状态以及此前推理轨迹。你的角色是仅基于可用证据执行当前推断步骤。你应产生能推进推理轨迹的中间推理输出。

必须遵守以下规则：

1. 只使用证据状态和此前推理轨迹中提供的累积证据。
2. 将当前推理步骤显式 grounded 到已检索证据中。
3. 不要引入没有支持的假设或外部知识，除非它已包含在证据状态中。
4. 除非当前子任务明确要求最终决策综合，否则不要回答最终问题。
5. 如果当前子任务证据不足，将缺失或不清楚的信息作为推理输出报告，以便规划器在下一步生成额外证据搜索查询。
6. 保持推理聚焦当前子任务，而不是一次性解决整个问题。

仅返回如下 JSON 对象：

```json
{
  "subtask": "<current sub-task>",
  "evidence_used": [
    "<relevant evidence item 1>",
    "<relevant evidence item 2>"
  ],
  "reasoning_output": "<intermediate result for the current sub-task>",
  "evidence_issue": "<None, or a description of insufficient evidence>"
}
```

如果可用证据足以完成当前子任务，将 `evidence_issue` 设为 `None`。如果可用证据不足，在 `evidence_issue` 中解释缺少什么证据，并且不要超出证据进行推断。

**用户输入。**

```text
Current Sub-task: {subtask}
Updated Evidence State: {evidence_state}
Previous Reasoning Trajectory: {reasoning_trajectory}
Return only the JSON object.
```
